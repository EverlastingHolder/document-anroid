# Инструкции для Android-клиента

Перед работой прочитай общий продуктовый и технический контекст в [`../passport-backend/README.md`](../passport-backend/README.md) и документы [`PRODUCT.md`](../passport-backend/docs/PRODUCT.md), [`ARCHITECTURE.md`](../passport-backend/docs/ARCHITECTURE.md), [`OCR.md`](../passport-backend/docs/OCR.md), [`TESTING.md`](../passport-backend/docs/TESTING.md), [`PLAN.md`](../passport-backend/docs/PLAN.md), а также API-контракт [`openapi.yaml`](../passport-backend/api/openapi.yaml). Backend — источник истины по API, общей архитектуре и правилам обработки данных. Не дублируй эти документы и не придумывай параллельный контракт.

Планируемый клиент: Kotlin, Jetpack Compose, CameraX, ViewModel с единым состоянием экрана и repository для сетевого обмена. Добавляй отдельные слои и абстракции только при появлении повторяемой доменной логики. API публичный; общий серверный ключ нельзя считать средством контроля доступа, если он встроен в APK.

OCR возвращает черновик, поля доступны для редактирования. В demo-режиме фейковые значения обозначает одна общая demo-плашка; отдельные маркеры проверки или распознавания полей и ручное подтверждение результата не показываются. Одна кнопка отправки валидирует текущие значения и при отсутствии ошибок экспортирует канонический `PassportSnapshot`, а не ответ OCR. Сохраняй актуальное состояние при повороте экрана через ViewModel; запоздавший ответ старого сканирования не должен подменять новое. Отказ в разрешении камеры должен оставлять путь через системный Photo Picker. Ошибки изображения, сети и сервера должны позволять повторить запрос с текущим изображением.

Реализованные изменения сверяй с общими документами. При работе с моделями используй практических workers `gpt-6-luna` с reasoning `high`, не более четырёх одновременно и без вложенной делегации. Главный агент отвечает за план, архитектурный разбор и оценку результата.
